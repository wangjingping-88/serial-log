# Ymodem 固件烧录

命令区的“Ymodem”页签用于向当前工作区勾选的多个本地串口窗口，并行发送同一个 `.bin` 固件。各窗口有独立的阶段、确认字节数、速度、耗时和结果；一个目标失败不停止其他目标。打开、隐藏、浮动命令区或切换工作区不会取消已经开始的烧录。

## 使用

1. 连接目标串口，在命令区左侧“目标窗口”勾选一个或多个本地窗口。Ymodem 页签不再单独选择目标，也不支持远程窗口烧录。
2. 选择模式，导入非空 `.bin` 文件。文件大小和路径会显示在页面中。
3. 停止涉及目标窗口的循环命令，再点击“开始烧录”。所选窗口、文件及规则方案在开始时固定，不随后续编辑或勾选变化而改变。
4. 查看每个窗口的进度和状态。“取消此窗口”仅取消对应目标；“取消全部”取消当前工作区本批次。离线、参数不符或循环占用的窗口会单独显示原因，其他合格窗口正常开始。

“自定义 Ymodem”执行“前置规则 → 通用 Ymodem → 后置规则”。前置和后置均可为空，每组可包含多个按序执行的步骤。规则设置支持多个命名方案的新建、复制、直接修改名称、删除和 JSON 导入／导出。方案、帧模板和选中方案独立保存在当前工作区中。导入时先完整校验，再追加新身份，不覆盖已有方案。

默认集成可编辑示例 `UCCHIP-小网关`：要求波特率 460800，先以 CTL=55 查询 UBOOT 配置，校验并要求 32 字节数据，复制配置后只将首字节改为模式 2，再通过 CTL=56 写回，断言响应去除尾部零填充后为 `suc`。首次独立 `C` 握手由传输引擎处理，规则中无需重复等待。该示例后置等待 `+SYSTEM:START`，超时 60 秒；Bootloader 自动重启，不额外发送重启指令。

方案允许要求指定波特率，0 表示不限。标准模式无固定波特率要求。用户删除或修改示例后，重启不会自动补回默认内容。

窗口选择的 COM 口和波特率必须与实际已打开的串口一致；连接期间修改过选择但尚未应用时，工具会提示重新连接，避免向原来的端口误发升级命令。

标准 Ymodem 模式使用窗口当前串口参数，不发送自动升级指令，也不执行规则方案；页面隐藏“规则方案”和“规则设置”，切回自定义模式后恢复显示，已保存的方案不变。需先由用户使设备进入 Ymodem 接收状态。设备已经停留在 Bootloader 时，也应选择标准模式。

每个工作区最多运行一个并行烧录批次。所有目标使用同一文件和规则快照，每个目标拥有独立的文件读取位置、规则变量、串口租约及取消令牌。文件在整个批次保持只读锁定。文件路径、模式、规则和左侧目标勾选随工作区保存；重启仅恢复配置，不启动任务。

## 规则与帧模板

支持发送、等待响应、请求／响应、修改字节、断言和可取消延时。发送可使用 UTF-8 文本及换行符、固定 Hex、字节变量或帧模板。等待可匹配文本、Hex 或完整协议帧；请求／响应先建立接收等待再发送，不自动重发有副作用的规则命令。修改字节按零基偏移复制后替换；断言支持长度、Hex 或精确文本，仅显式启用时去除末尾零填充。

变量只在单次目标任务内共享，前置可供后置引用，不随配置持久化。帧响应变量保存载荷，字段可用 `变量名.字段名` 引用；文本或 Hex 响应保存命中的序列。变量总量上限 1 MiB，接收和帧缓冲上限 64 KiB，超限明确失败。

帧模板由有序的固定 Hex、整数、载荷长度、载荷和校验字段组成，且包含恰好一个载荷字段。整数及长度支持 1／2／4 字节和大小端；载荷可定长或引用前置长度字段；发送自动重算长度和校验。校验支持 Sum8、Xor8、CRC16/XMODEM，可设置之前连续字段的覆盖范围和 CRC16 输出端序。不需要校验时不添加校验字段。Hex 不带 `0x`，例如 `AA 01`；整数使用十进制。

`UCCHIP-小网关` 示例模板为 `AA 01`、4 字节小端地址 0、CTL、2 字节小端载荷长度、载荷、Sum8、`EE`，校验从帧头至载荷末尾。响应验证固定字段、长度、校验和指定整数值，不预取帧后的握手字节。

## 运行限制与恢复

- 烧录期间目标显示“烧录中”，禁止普通发送、协作远程发送、参数修改和串口转移。后续改变其他窗口勾选不会加入当前批次。
- 批量连接、断开跳过烧录目标并显示提示。删除窗口、停止工作区或退出应用时先确认，再取消并等待任务释放。
- 目标的静默重连与自动重连暂停，失效句柄仍会被检测。其他窗口和工作区的采集、保存及协作继续运行。
- 隐藏按钮位于“浮动”旁；浮动命令区也有隐藏按钮。通过“视图”菜单重新显示。
- 取消或失败不会自动重烧。串口失效后需手动重连；设备可能仍在 Bootloader，此时可使用标准模式重新传输。

## 完成状态

进度按收到 ACK 的实际固件字节计算，重传不重复增加进度。达到 100% 后还需要 EOT、空文件头和最终 ACK，才能显示“文件传输完成”。

前置失败或取消，不开始传输；传输失败或取消，不执行后置。最终 ACK 后执行后置规则，后置等待文本时同步展示普通日志，仍使用同一个独占通道。后置失败或取消显示“文件传输完成，后置规则未完成”，并说明步骤和原因，不把已完成的文件传输改为失败。

后置匹配成功不等于固件版本验证成功。即使示例检测到 `+SYSTEM:START`，仍需人工确认设备功能和版本。

目标日志记录文件名、大小、SHA256、阶段、重传及结果，二进制控制字节不作为普通日志保存或共享。非 ASCII 或过长的文件名在 Ymodem 文件头中使用 `firmware.bin`，本地显示原文件名。

## 开发验证

自动测试覆盖通用传输、可配置校验和端序、空规则、步骤顺序、变量传递与越界、帧尾随 C、后置启动文本不丢失、不重复展示、分阶段失败、取消释放、并行目标相同文件、单窗口失败／取消隔离、后台工作区、旧配置无损迁移、备份及原子保存失败保护。WPF 渲染测试检查宽、窄布局和实际绑定。

旧单目标小网关流程已经实机验证成功（1,986,392 字节，约 1 分 22 秒）。本次规则化和多目标并行修改已通过自动测试，仍需使用 `UCCHIP-小网关` 复验，并验证多窗口同时烧录、取消单个目标、标准模式及异常恢复。

工作区配置格式由 2 升级为 3，旧 `Gateway` 模式迁入自定义方案。迁移先保存原文件备份，再原子写入；旧目标 ID 不再作为 Ymodem 独立选择，实际目标以原有左侧发送勾选为准。预览覆盖只替换程序文件，完整保留 `data`。
